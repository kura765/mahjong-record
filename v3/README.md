## 操作の概要

1. `v3/cloud.html` で開発用Supabaseへ接続し、メールリンクでログインする。
2. 作成者が非公開ルームを作り、必要なら招待リンクを発行する。
3. `v3/play.html` で**試験用**の対局を入力する。
4. クラウド画面で試験用バックアップの内容を確認し、初回取り込みを実施する。
5. 後続の変更は手動更新か、明示的に開始したフォアグラウンド自動反映でアップロードする。
6. クラウドから端末へ反映する場合は差分確認とバックアップ保存を行い、手動で取り込む。

ローカル保存領域は `mahjongV3Trial`。既存v2.22の `mahjongPrototypeV1` とは別です。NetlifyとGitHub Pages間のようにドメインが違う場合、ローカルストレージは共有されません。JSONバックアップを利用してください。

**重要な制限**：未検証の本番記録をいきなりアップロードしないでください。進行中の本番対局にはまだ使わないでください。完全自動の双方向同期と複数人同時編集は未完成です。

## 競合後の安全な復旧（2026-11-26）

異なる端末で同じ半荘に異なる操作を行った場合、通常の「差分を確認」は引き続き拒否します。新しい **「競合した半荘はクラウド優先で比較」** は、明示的にクラウド側を採用したい場合だけ使う機能です。

1. 端末のv3.0試験入力とクラウドの自動反映を停止する。
2. 元の端末で「試験入力バックアップ」をJSONで書き出し、保存先にファイルがあることを確認する。既にバックアップがあっても、再度最新のものを保存することを推奨。
3. クラウド画面で対象ルームを選び「競合した半荘はクラウド優先で比較」を押す。クラウドで採用する件数・半荘を確認する。
4. 「現在の試験入力をバックアップ」からJSONを書き出して内容を保管した後、確認欄にチェックを入れて取り込みを実行する。
5. 試験入力画面を再読み込みして内容を確認する。最後にクラウド画面から通常の「差分を確認」を押し、競合が残っていないか検証する。

この処理は、競合対象についてクラウドを優先してローカルを置き換え、その他のローカルだけの変更は可能な限り保全します。クラウドにアップロードはしません。既存のv2.22の記録を読み書きしません。新規ID重複・メタデータ不一致・クラウド側の変更を検出した場合には実行を拒否します。実行直前にローカルの元データとクラウドの指紋を再検証します。

ローカルに競合対象の記録がクラウドと完全に一致している場合は、端末側のデータを変更せず、古い同期基準だけ更新することもできます。競合採用を含むロジックのJavaScript検証は通過しましたが、**iPhoneの新操作は実機未検証**です。バックアップ確認前に実行しないでください。

## かんたん同期の導線（2026-11-26）

- クラウドの画面上部に「同期する（変更を確認）」を追加。**最初の操作は必ず読み取り専用**で、クラウド・端末の差分比較と競合チェックだけを実行する。
- クラウド側に未取得の記録や同期基準の更新がある場合は、先に既存の「差分を確認」・バックアップ・取り込み操作へ案内する。未取得がある状態では送信候補を提供しない。
- 未送信の変更のみの場合は、既存の「更新候補を調べる」・半荘ごとの確認・保存操作へ案内する。
- 競合時は停止。別アカウント（閲覧専用）の書き込み操作は許可しない。自動反映中はこの導線を利用できない。
- **これは一括自動同期ではなく、安全な案内・差分確認の簡略化**。確認なしの一括上書きや書き込みはまだ追加していない。
- 静的JS構文検査と4分岐（未送信／未取得／変更なし／競合）のロジック検査を実施。iPhone実機操作は未検証。
